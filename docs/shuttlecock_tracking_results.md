# 셔틀콕 추적 검증 결과

재현:

```bash
python3 tools/test_shuttlecock_tracking.py --verbose
```

측정은 합성 영상으로 한다. 실제 실험 영상에는 사람이 만든 기준 궤적밖에 없고 그 기준
자체가 오차를 포함하므로, 추적 오차와 기준 오차를 분리할 수 없다. 합성 영상은 궤적을
수식으로 먼저 정하고 그 자리에 셔틀콕을 그리므로 **오차 없는 기준 궤적**이 존재한다.
영상 조건(960×540, 120 fps, 70프레임, 항력이 있는 포물선, 코트 배경 + 잡음)과 셔틀콕
구조(코르크 헤드 + 깃대 16개 스커트, 손상 조건은 깃대 제거로 구현)는
`tools/make_synthetic_shuttlecock.py` 에 있다.

눈금은 300 px = 1 m, 질량 5 g, 스커트 지름 66 mm 로 두고 물리량을 계산했다.

## 2. 어려운 상황

| 조건 | MAE (px) | RMSE (px) | 최대 (px) | 성공률 | 손실 | 속도오차 | 물리량 최대오차 |
|---|---|---|---|---|---|---|---|
| 배경과 비슷한 색 (배경 밝기 150) | 0.34 | 0.40 | 1.29 | 100.0 % | 0.0 % | 2.2 % | 1.90 % |
| 일시적 가림 (프레임 24–31 완전 차폐) | 1.55 | 10.01 | 78.80 | 88.6 % | 11.4 % | 7.2 % | 2.72 % |
| 긴 비행 구간 (140프레임 + 크기 25% 감소) | 0.75 | 2.40 | 18.93 | 89.3 % | 10.0 % | 5.6 % | **22.00 %** |

**신뢰(HIGH/MEDIUM) 프레임만 놓고 본 최대 위치 오차**

| 조건 | 신뢰 프레임 수 | 최대 오차 |
|---|---|---|
| 배경과 비슷한 색 | 69 | 1.3 px |
| 일시적 가림 | 60 | 0.7 px |
| 긴 비행 구간 | 121 | 3.3 px |

큰 오차(78.8 px, 18.9 px)는 모두 `LOW` + `RECOVERED`/`PREDICTED` 로 기록되고 이상 프레임
목록에 자동으로 오른다. 즉 **실패가 정상 데이터로 위장되지 않는다.** 가림 구간 24–31 에서
기록된 것은 1프레임뿐이고 그마저 `RECOVERED` / confidence 0.38 이며, 나머지 7프레임은
좌표를 지어내지 않고 비워 뒀다.

### 긴 비행 구간의 C_D 오차 22 % — 무엇을 뜻하는가

이 조건에서 위치 오차는 MAE 0.75 px 로 작지만 C_D 오차는 22 % 다. 이것이 **위치 정확도만
보고 물리 데이터의 품질을 판단하면 안 되는 이유**다.

- 위치 → 속도 → 감쇠율로 두 번 미분하면서 오차가 증폭된다.
- 이 조건에서는 셔틀콕이 25 % 작아지는 동안 물체 분리에 실패한 프레임이 8개 있었고, 그
  프레임은 상자 중심으로 대체됐다(`center_method` 열에 `(fallback)`). 중심 정의가 서서히
  달라지면 위치 오차로는 잘 드러나지 않지만 감쇠율에는 그대로 남는다.
- 판정 기준(물리량 상대오차 5 % 이하)은 이 조건을 **탈락**시킨다. 그것이 의도된 동작이다.

`v0`(0.51 %), 비행시간(0 %), 도달거리(2.03 %), 최고높이(0.02 %), 평균속력(0.48 %)은 이
조건에서도 정확하다. 즉 이 궤적은 운동학 분석에는 쓸 수 있고 항력 계수 추정에는 부족하다.

|---|---|---|

\* 이 측정에서는 상자를 정답 위치에 고정해 두고 쟀으므로 0 이 나온다. 실제 추적에서는
상자 자체가 추적기 출력이라 이 값은 하한이다.

`auto` 가 `cork_center` 를 고르는 근거가 이것이다.

## 4. 중심 정의 일관성 · 데이터 무결성

- 7개 조건 **전부**에서 `auto` 가 같은 정의(`cork_center`)로 수렴했다.
- 한 실행 안에서 그 정의를 적용하지 못한 프레임 비율: 6개 조건 0.0 %, '작게 보임' 조건만
  7.2 % (해당 프레임은 `center_method` 열에 `(fallback)` 으로 표시되고 실행 로그에 남는다).
- 예측(`PREDICTED`) 프레임이 `HIGH`/`MEDIUM` 으로 기록된 경우: **0건**.
- 예측 프레임의 confidence 가 0.5 를 넘은 경우: **0건**.

## 5. 회귀 확인 — 기존 profile 이 그대로인가

같은 영상, 같은 시드로 세 profile 을 비교했다.

| Profile | 기록 프레임 | MAE | 최대 | 처리속도 | 중심 정의 |
|---|---|---|---|---|---|
| Generic | 60/60 | 2.47 px | 3.38 px | 49.9 fps | `blended` (기존 동작) |
| Pendulum | 60/60 | 2.47 px | 3.38 px | 77.5 fps | `blended` (기존 동작) |
| Shuttlecock | 60/60 | **0.29 px** | **0.69 px** | 58.2 fps | `cork_center` |

Generic / Pendulum 의 결과는 변경 전과 동일하다. 셔틀콕 전용 처리(배율 허용 외형 비교,
색 히스토그램 거부권 제한, 깃털을 남기는 마스크, 진행 방향 제약)는 모두
`Profile = Shuttlecock` 에서만 켜진다.

처리 속도는 960×540 · CPU 단독(GPU 없음) 기준 50–78 fps 로 변경 전과 같은 수준이다.
단계적 ROI 재탐색이 전체 프레임 재탐색을 줄이므로, 추적을 자주 놓치는 영상에서는 오히려
빨라진다.

## 6. 결론 — 이 시스템의 추적 결과를 실제 물리 연구 데이터로 사용해도 되는가

**조건부로 그렇다. 그리고 그 조건은 프로그램이 영상마다 스스로 판정한다.**

측정된 근거:

| 판정 기준 | 기준값 | 정상·손상 7조건 실측 | 어려운 3조건 실측 |
|---|---|---|---|
| 위치 RMSE / 셔틀콕 크기 | ≤ 0.25 | 0.007 – 0.029 | 0.009 – 0.24 |
| 추적 성공률 | ≥ 95 % | 98.6 – 100 % | 88.6 – 100 % |
| 손실 프레임 비율 | ≤ 5 % | 0 – 1.4 % | 0 – 11.4 % |
| 속도 오차 | ≤ 10 % | 1.5 – 5.4 % | 2.2 – 7.2 % |
| 물리량 상대오차 (최대) | ≤ 5 % | 0.75 – 3.26 % | 1.90 – **22.0 %** |

- **정상·손상 셔틀콕 7개 조건에서는 다섯 기준을 모두 통과한다.** 손상 조건(2/4개,
  대칭/비대칭) 사이의 물리량 오차 차이가 1 % 이내이므로, 손상 조건을 비교하는 실험에
  쓸 수 있다.
- **어려운 조건에서는 통과하지 못하는 항목이 나온다.** 긴 비행 + 크기 감소 조건은 C_D
  오차 22 % 로 탈락하고, 가림 조건은 손실 프레임 11.4 % 로 걸린다. 두 경우 모두
  프로그램이 "조건부" 또는 "사용 불가"로 판정하고 어느 항목이 왜 걸렸는지 표시한다.
- **어떤 조건에서도 실패가 정상 데이터로 위장되지 않는다.** 큰 오차는 전부 `LOW` +
  `RECOVERED`/`PREDICTED` 로 기록되고 이상 프레임 목록에 오른다. 예측 프레임이
  `HIGH`/`MEDIUM` 으로 저장된 경우는 0건이다.

따라서 실제 사용 절차는 다음과 같아야 한다.

1. 대표 영상 몇 개에 대해 기준 궤적(수동 annotation)을 만든다.
2. **추적 검증**을 돌려 그 촬영 조건에서의 다섯 기준을 확인한다.
3. 통과하면 같은 촬영 조건의 나머지 영상에 적용한다.
4. 이상 프레임 목록을 확인하고 필요하면 수동 수정 + 국소 재추적을 한다.
5. CSV 의 `source` 열로 예측 프레임을 빼고 다시 계산해 결과가 달라지는지 확인한다.

여기서 검증하지 않은 것: 이 결과는 모두 **합성 영상**에서 나왔다. 합성 영상은 배경이
단순하고, 셔틀콕의 3차원 자세 변화(turnover)와 렌즈 왜곡, 압축 노이즈, 조명 변화가 없다.
실제 실험 영상에서의 성능은 위 1–2단계를 직접 수행해 확인해야 한다. 프로그램이 그 절차를
위해 존재한다.
